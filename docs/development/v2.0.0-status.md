## 3. OPEN_DESIGN / COMMERCIAL_DECISIONS

以下问题不应由源码拍脑袋决定，需要后续真实测试或商业策略讨论：

1. 自动模式的费用授权粒度与默认 Take / Retry 预算。
2. 达到多少次有针对性失败后默认建议 Manual Takeover。
3. Shot Diversity 不同套餐/创意方向的评分与软阈值校准。
4. 五分钟产品的套餐时长梯度和商业交付层级。
5. 客户直销、自助式产品、摄影工作室 B2B 或混合服务的最终商业形态。
6. QC 中哪些域可以完全自动检查，哪些必须人工/客户确认。
7. 小云雀资产板非生成式排版与项目状态长期保存的最佳实现方式。
8. 是否、何时把历史 Doubao Adapter 重新升级到 v2 Core。

## 4. NEXT DEVELOPMENT ORDER

建议按以下顺序继续：

1. **CI / Source Integrity**：确保 v2 Active Canon、references、Runtime 与 validator 全绿。
2. **Runtime Capability Probe**：小云雀当前账号模型/工具矩阵。
3. **Identity E2E**：真人参考 → Retouch → 9 images → Approval。
4. **Look E2E**：AB04/05 首版妆造 + 局部改妆。
5. **Photo E2E**：AB06 → DIR01 → Shot List → 一套完整商业照片。
6. **VF01 E2E**：Approved Photo → VB01 → Shot/Take → Picture Lock → Music/Post。
7. **VF02 E2E**：Story Gate → Breakdown → Story Assets → Storyboard Gate → Film。
8. **VF03 E2E**：双线资产 → Bridge → Continuity → Final Master。
9. **Commercial Pilot**：记录成本、重试、人工介入、客户审批和交付反馈。
10. **v2.0.0 Release Gate**：只有 Runtime 回归通过后再编译/发布。

## 5. RELEASE BLOCKERS

在以下项目没有证据前，不应发布稳定 v2.0.0：

- v2 CI / Source Validator PASS；
- 9-image identity workflow 至少一组完整 E2E；
- Explicit Makeup + Look Identity Gate 实测；
- Photo DIR01 / Shot coverage 完整案例；
- VF01/VF02/VF03 至少各有一个受控流程验证（可先短片，不要求一开始就五分钟）；
- 小云雀关键模型/工具 Capability Matrix 有实际状态；
- No-BGM / Story/Storyboard Gate / Scoped Revision 的行为得到验证；
- 项目状态恢复至少明确属于 PERSISTED / SESSION_ONLY / UNKNOWN 中哪一种。

只有用户明确要求“编译”时才进入正式构建/打包阶段。
